## Section 1. 프로세스의 이해 (개념)

### 프로세스란
- **프로세스** = 현재 시스템에서 실행 중인 프로그램
- 리눅스는 **다중 프로세스 시스템** (여러 프로세스 동시 실행)
- 시스템 프로세스(운영에 필요) / 사용자 프로세스(사용자가 실행)

### 부모-자식 관계와 PID
- 모든 프로세스는 **부모-자식 관계**로 연결된 트리 구조
- **PID** = 프로세스를 고유하게 식별하는 번호 (1번부터 증가)
- **PID 1번 = `systemd`** → 모든 시스템 프로세스의 조상
- **PID 2번 = `kthreadd`** → 모든 스레드의 조상
- 부모가 자식을 생성, 자식은 끝나면 결과를 부모에 반환 후 종료

### 특수 프로세스 4종 (시험 포인트)

| 종류 | 정의 | 핵심 |
|------|------|------|
| **데몬(daemon)** | 특정 서비스 제공, 평소 대기하다 요청 시 실행 | `sshd`, `httpd` |
| **부모(parent)** | 자식 프로세스를 만드는 프로세스 | — |
| **자식(child)** | 부모가 생성, 끝나면 결과 반환 후 종료 | — |
| **고아(orphan)** | 부모가 **먼저** 종료된 자식 | **PID 1번이 새 부모로 입양** |
| **좀비(zombie)** | 종료됐지만 부모가 종료 정보를 **회수 안 함** | `defunct` 표시, 자원 낭비, **SIGKILL로도 안 죽음** |

> **고아 vs 좀비**: 고아는 *부모가* 죽음(자식은 살아 있음) / 좀비는 *자식이* 죽음(부모가 정리 안 함)

## Section 2. 프로세스 관리 명령

### 2-1. 프로세스 조회: `ps`

```
ps [옵션]
```

**SVR4 스타일 (옵션에 `-` 붙음)**

| 옵션 | 의미 |
|------|------|
| `-e` | 시스템의 **모든** 프로세스 |
| `-f` | **상세 정보** (PPID = 부모 PID 포함) |
| `-u UID` | 특정 사용자의 프로세스 |
| `-p PID` | 특정 PID의 프로세스 |
| `ps -ef` | 전체 + 상세 (가장 많이 씀) |

**BSD 스타일 (옵션에 `-` 없음)**

| 옵션 | 의미 |
|------|------|
| `a` | 터미널에서 실행된 모든 프로세스 |
| `u` | 상세 정보 (CPU·메모리 사용량 포함) |
| `x` | 터미널과 무관한 프로세스까지 (백그라운드 포함) |
| `ps aux` | 전체 + 상세 (가장 많이 씀) |

- `TTY`가 `?` → 시스템에서 실행된 프로세스 (터미널 없음)
- `STAT` 필드 = **BSD 옵션에서만** 출력, 프로세스 상태를 문자로 표시 (예: `Ss+`)
- 스레드는 `CMD`에 `[]`로 표시

### 2-2. 프로세스 검색: `grep` / `pgrep`

```
ps -ef | grep 패턴        # ps와 grep을 파이프로 연결
pgrep [옵션] 패턴          # ps+grep을 하나로 통합, PID 출력
```

| `pgrep` 옵션 | 의미 |
|------|------|
| `-x` | 패턴과 **정확히** 일치 |
| `-l` | PID + 명령 이름 함께 출력 |
| `-u` | 특정 사용자의 프로세스만 |
| `-t` | 특정 터미널 관련 프로세스만 |

- 기본적으로 `pgrep`은 **PID만** 출력 → 상세 정보는 `ps`와 연결

### 2-3. 프로세스 종료: `kill` / `pkill` / `killall`

| 명령 | 인자 | 특징 |
|------|------|------|
| `kill` | **PID** 또는 **`%작업번호`** | 소유권 있어야 종료 가능 |
| `pkill` | **이름(패턴)** | 같은 이름 프로세스 한 번에 종료 |
| `killall` | **이름(CMD)** | 패턴에 맞는 모든 프로세스 종료 |

```
kill PID            kill %1            kill -9 PID
pkill man           killall man
```

- 프로세스를 종료하면 **자식 프로세스도 함께** 종료
- `%작업번호`는 **`kill`만** 사용 가능 (`pkill`/`killall`은 이름만 받음)

### 2-4. 우선순위 조정: `nice`

- 프로세스의 **실행 우선순위** 조정 (작업 번호와 무관!)
- 범위: **`-20`(가장 높음) ~ `19`(가장 낮음)**, 기본값 **0**
- 우선순위 높을수록 자원을 많이 받아 빠르게 실행
- **음수는 root만** 지정 가능 (일반 사용자는 불가)
- `ps -l`로 현재 nice 값 확인

```
nice -n 5 man ls       # nice 값 5로 man 실행
```

### 2-5. 모니터링: `top`

- 실행 중인 프로세스 정보를 **주기적으로 실시간** 출력
- 상단 = 요약 정보(부하·메모리 등), 하단 = 프로세스별 세부 정보
- 종료: **`q`**
- 메모리 관찰: `top`, `free`, `sar`, `cat /proc/meminfo | grep Mem`

## Section 3. 작업 제어 (Job Control)

### 핵심 개념
- **작업(job)** = 셸이 프로세스를 관리하는 단위 (Job ID 부여)
- 작업 번호 `[n]`은 **셸**이 매김 / PID는 **시스템**이 매김 → **서로 다름**
- 한 작업이 **여러 프로세스**를 포함할 수 있음 (파이프라인)

### 포그라운드 vs 백그라운드

| 구분 | 포그라운드 | 백그라운드 |
|------|-----------|-----------|
| 처리 | 결과 나올 때까지 **기다림** | 바로 다음 프롬프트 출력 |
| 터미널 | 작업이 **독점** | 점유 안 함 |
| 실행 | 그냥 명령 | 명령 끝에 **`&`** |

### 작업 제어 명령

| 명령 | 동작 |
|------|------|
| `jobs` | 백그라운드/정지 작업 목록 (현재 셸 한정) |
| `Ctrl + Z` | 포그라운드 작업 **일시 중지** |
| `bg %번호` | 정지된 작업을 **백그라운드**로 |
| `fg %번호` | 작업을 **포그라운드**로 (번호 생략 = 최근 작업) |
| `Ctrl + C` | 포그라운드 작업 **종료** |
| `kill %번호` | 작업 번호로 종료 |

**작업 번호 참조 기호**

| 표기 | 의미 |
|------|------|
| `%번호` | 해당 번호 작업 |
| `%+` 또는 `%%` | **가장 최근** 작업 (current) |
| `%-` | **직전** 작업 (previous) |

> `jobs` 출력의 `+`/`-`는 우선순위가 아니라 **"최근 다룬 순서"**

### 로그아웃 후에도 유지: `nohup`

```
nohup 명령 &
```
- 터미널 종료/로그아웃 후에도 백그라운드 작업 **계속 실행**
- 결과·오류 → 기본적으로 **`nohup.out`** 파일에 저장
- 출력 방향 전환 시 지정한 파일에 저장 가능

### 입출력 처리 (질문 정리)
- 입력 필요 → **리다이렉션 `<`**
- 출력 저장 → **리다이렉션 `>`** 또는 `script`
- 다른 프로그램 출력 받기 → **파이프라인 `|`**

## 시그널 (Signal)

- **시그널** = 예기치 않은 상황을 프로세스에 전달하는 간단한 메시지
- 번호로 정의, 각 번호마다 고유 이름
- 목록 확인: **`kill -l`**
- `kill`은 시그널 번호/이름으로 프로세스에 전송

| 번호 | 이름 | 의미 |
|:---:|------|------|
| **2** | `SIGINT` | `Ctrl + C`로 발생, 인터럽트 종료 |
| **15** | `SIGTERM` | **`kill`의 기본값**, 정상 종료 요청 |
| **9** | `SIGKILL` | **강제 종료**, 무조건 종료 (단, **좀비는 안 죽음**) |

```
kill PID            # 기본 = 15(SIGTERM)
kill -9 PID         # 강제 종료(SIGKILL)
kill -15 PID        # 명시적 SIGTERM
```

- 프로세스는 시그널을 **무시하거나 다르게 처리**하도록 설정 가능 → SIGTERM은 무시될 수 있음
- SIGKILL(9)은 무시 불가 → 그래서 강제 종료용

## 핵심 비교 한눈에

| 헷갈리는 쌍 | 차이 |
|------------|------|
| 작업 번호 `%1` vs PID `4521` | 셸이 매김 / 시스템이 매김 |
| 고아 vs 좀비 | 부모가 죽음 / 자식이 죽고 부모가 방치 |
| `ps -ef` vs `ps aux` | SVR4 / BSD 스타일 (둘 다 전체+상세) |
| `Ctrl+Z` vs `Ctrl+C` | 일시 중지 / 종료 |
| SIGTERM(15) vs SIGKILL(9) | 정상 종료(무시 가능) / 강제 종료(무시 불가) |
| `kill` vs `pkill`/`killall` | PID·작업번호 / 이름 |
